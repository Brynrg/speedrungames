# Speed Run Games

Browser game portal. Live at **[speedrungames.net](https://speedrungames.net)**.

This monorepo is the umbrella: it hosts the Next.js portal site, the per-game
manifests, and the canonical scripts for ingesting games into the catalog.

## Adding a new game (the agent-driven flow)

Point any AI coding agent at this repo and tell it what you want:

> **"Read https://github.com/Brynrg/speedrungames/blob/main/AGENTS.md and
> follow it. Build me a game for: \<one-sentence spec\>."**

The agent will:

1. Read [`AGENTS.md`](./AGENTS.md) — the canonical contract.
2. Fork [`Brynrg/speedrungames-game-template`](https://github.com/Brynrg/speedrungames-game-template) into a new repo for the game source.
3. Build the game per [`docs/browser-game-template-contract.md`](./docs/browser-game-template-contract.md) — must produce `dist/index.html`.
4. Run `node scripts/ingest-game-build.mjs --game-dir <path>` from inside this repo to copy the build into [`apps/web/public/games/<slug>/`](./apps/web/public/games/) and write the portal manifest.
5. Open a PR against `main` here.

When you merge the PR, Netlify auto-deploys and the game appears at
`https://speedrungames.net/games/<slug>/`.

Multiplayer games are allowed but must use one of the approved free-tier
patterns in [`docs/multiplayer-architecture.md`](./docs/multiplayer-architecture.md).
Games with their own backend should also carry a `DEPLOYMENT.md` in their
source repo (see [`Brynrg/Tank-you-again`](https://github.com/Brynrg/Tank-you-again) for the reference shape).

## Repo layout

```
speedrungames/
├── apps/web/                              # Next.js 16 portal site (Netlify)
│   ├── public/games/<slug>/               # Built static game drops + portal manifest
│   └── src/lib/games.registry.json        # Generated catalog — DO NOT hand-edit
├── games/pokemonspeedrungen1/             # In-repo game workspace (legacy embed)
├── scripts/
│   ├── ingest-game-build.mjs              # Canonical "ingest a built game" entrypoint
│   ├── build-registry.mjs                 # Regenerate games.registry.json from manifests
│   └── validate-games.mjs                 # Schema + path-soundness checks
├── schemas/portal-game-manifest.schema.json
├── docs/                                  # Browser template contract, multiplayer, autonomy levels
├── AGENTS.md                              # The portal contract — agents read this first
└── netlify.toml
```

## Local dev

```bash
pnpm install
pnpm dev                 # → http://localhost:3000
```

Useful one-shots:

```bash
pnpm run build:registry  # Rebuild games.registry.json from per-game manifests
pnpm run validate:games  # Lint manifests + check that index.html / status / paths agree
pnpm -C apps/web build   # Production Next.js build (CI uses this)
```

## Hard rules (excerpted from AGENTS.md)

- No direct push to `main`. PRs only.
- No secrets in code or manifests.
- No external CDNs without a vendored fallback.
- No always-on paid servers; multiplayer must declare its free-tier pattern in the game's `game.manifest.json`.
- Don't hand-edit `apps/web/src/lib/games.registry.json` — regenerate it with `pnpm run build:registry`.

See `AGENTS.md` for the complete list.
